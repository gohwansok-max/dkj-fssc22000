# V2 전환 이후 후속 작업 계획

> 이 문서는 현재 초안 PR #6, #7, #8의 검토·병합 이후 진행할 작업 순서입니다. 실제 HACCP 기준값이나 인증기관 전환일은 추측하지 않고, 확정 자료를 받은 뒤에만 시스템에 반영합니다.

## 1. V2 실제 전환 전 필수 작업

| 순서 | 작업 | 필요한 입력 | 완료 기준 |
|---:|---|---|---|
| 1 | Firebase Rules Simulator 검증 | 실제 테스트 사용자 UID 2개 이상 | 작성자 본문 수정 허용, 타인 수정 거부, 잠금 후 본문 수정 거부, 결재·감사이력 추가 규칙을 캡처로 보관 |
| 2 | 역할의 서버 강제 설계 | 작성·검토·승인·관리자별 실제 사번과 직무 | Firebase Custom Claims 또는 보호된 사용자 역할 노드를 적용해 UI 역할표와 DB 권한을 일치 |
| 3 | 전체 백업·UID 매핑 | RTDB 전체 JSON, Firebase 사용자 UID 목록 | 마이그레이션 보고서 `safeToImport: true`, 오류 0건 |
| 4 | 테스트 기기 검증 | PC 1대, 태블릿 1대, 테스트 계정 2개 | 오프라인 작성·온라인 복귀·충돌·권한 거부·정본 인쇄 통과 |
| 5 | 운영 전환 | 운영 책임자와 전환 시간 | `records_v2` import, 규칙 게시, schemaVersion 2 설정, 기록 수·잠금·결재이력 대조 |

## 2. P1 기능 구현 순서

### 2.1 CCP 이탈 사건·CAPA 폐쇄루프

CCP X 판정에서 사건번호를 생성하고, 영향 LOT·격리 위치·재검사·원인분석·시정조치·조치기한·유효성 확인·승인을 하나의 사건으로 연결합니다. 구현 전에는 부적합 등급, 사건번호 채번 규칙, 담당부서, 기한 산정 기준, 효과검증 승인자를 확정해야 합니다.

### 2.2 생산일·비생산일 통제

생산계획 또는 생산일보를 기준으로 일일 기록 대상일을 계산합니다. 비생산일은 `휴무`, `설비보전`, `원료미입고`, `계획생산없음`, `기타` 등 사업장이 승인한 사유코드와 승인자·승인시각을 남겨 미작성 경보에서 제외합니다. 구현 전에는 실제 생산계획 작성 주체와 확정 시점을 확인해야 합니다.

### 2.3 CCP 기준 마스터

설비·품목·중량 구간·공정별 한계기준을 코드에서 분리합니다. 각 기준에는 개정번호, 시행일, 근거 문서, 승인자, 폐기일을 둡니다. 금속검출 물성보정값과 소독·헹굼 기준은 HACCP 관리기준서 확정본에서 받습니다.

### 2.4 백업·복구·동기화 경보

브라우저의 잠깐 표시되는 동기화 실패를 로컬 운영 로그로 남기고, 관리자 화면에서 최근 성공·실패·미동기화 건을 보게 합니다. Firebase의 예약 백업 가능 범위도 확인해 일일 백업과 월간 복구시험 책임자를 절차서에 지정합니다.

## 3. 서버 측 신뢰성을 더 높이기 위한 결정

현재 Firebase 규칙은 기록의 최초 작성자와 잠금 상태를 검증할 수 있지만, 감사이력을 **서버가 생성하거나 서명하는 구조는 아닙니다**. 감사로그의 절대적 신뢰성과 단계별 결재 역할을 DB에서도 강제하려면 Firebase Cloud Functions 또는 별도 API가 필요합니다. 이 선택은 정적 사이트 중심 구조를 확장하는 결정이므로, 비용·운영 담당자·장애 대응 방식을 정한 뒤 착수합니다.

## 4. FSSC V7 전환

FSSC V7 적용일은 인증기관의 전환 계획과 사업장 인증 주기에 따라 확정합니다. 이후 영향평가표, 문서·MDR 개정, 교육, 내부심사, 경영검토를 하나의 전환 대장으로 연결합니다. 상단의 V6 표기는 이 전환 계획과 문서 개정이 완료된 뒤에 변경합니다.
