# 자가품질검사·보건증 스케줄러 (정기 알림 화면의 '자가품질검사 · 보건증' 탭)

코엔에프 `conf-quality-scheduler`(Supabase 기반 단일 페이지 앱)의 기능을 동김제 시스템 구조에 맞춰 이식했다. 2026-10-27.

## 정기 알림과 한 화면으로 통합 (2026-10-27)

`periodic-alerts.html` 위쪽에 두 탭이 있다: **정기 관리 항목**(계측기 검교정·환경모니터링·이메일 자동 발송) / **자가품질검사 · 보건증**(이 문서의 기능). 주소는 `periodic-alerts.html#quality`(탭별 `#quality-products` 등). `quality-scheduler.html`은 옛 북마크용 이동 페이지만 남겼다.

- 정기 관리 항목의 엑셀 양식·가져오기·내보내기도 두 유형을 막았다(`js/periodic-alert-excel.js` `BLOCKED_TYPES`): 양식 드롭다운에서 제외, 해당 유형 행은 행 번호와 사유로 업로드 차단, 내보내기에서 제외(옛 항목은 저장소에 그대로 남음).
- 자가품질검사·보건증의 정본은 이 탭 하나다. 정기 관리 항목에서는 두 유형을 새로 등록할 수 없고, 기본 시드 항목에서도 뺐다.
- **이미 정기 관리 항목에 입력된 자가품질검사·보건증 항목은 자동 이관하지 않는다**(제품·식품유형 기반 vs 단순 예정일 구조라 1:1 변환이 안 된다). 화면에 안내 띠가 뜨며, 새 탭에 등록한 뒤 옛 항목은 `알림 관리에 포함`을 꺼야 알림이 이중으로 나가지 않는다.
- `functions-periodic`(이메일)은 정기 관리 항목만 읽으므로 옛 항목을 끄면 이메일에서도 빠진다. 텔레그램은 이 탭의 데이터(`QS-ITEMS`)만 본다.

## 기능

| 탭 | 내용 |
|---|---|
| 대시보드 | 제품별 다음 검사 마감일·D-Day, KPI 5종, 보건증 월별 만료 막대, 식품유형×월 마감 매트릭스, 빠른 검사 갱신, 필터 |
| 제품·검사 관리 | 제품 등록·수정·삭제, 생산 중단(사유)·알림 중지, 갱신 이력, 엑셀 양식·가져오기 |
| 식품유형 관리 | 유형별 검사주기·시험항목, 대시보드 대표 제품 고정, 대시보드 표시 여부 |
| 보건증 관리 | 등록·수정·퇴직 제외·알림 중지, 사본 보관(PDF·이미지), 알림 시험 발송 |
| 성적서 관리 | 성적서 번호 자동 채번(접두어·일련번호), 파일 보관, 유형별 검색 |
| 설정·알림 | 사전 알림 일수, 보건증 알림 기준일(기본 D-30·7·1), 텔레그램 연결 상태·즉시 발송 |

## 구조 (코엔에프 원본과 다른 점)

| 항목 | 원본 | 동김제 |
|---|---|---|
| 데이터 | Supabase 테이블 6개 | 서식 `QS-ITEMS` 하나의 기록 목록(`kind` = type/product/history/health/cert/setting) → `DkjRecordStore`(IndexedDB + RTDB 동기화) |
| 파일 | Supabase Storage(공개 버킷) | RTDB `records/<nodeKey('dkj:qsfile:<id>:v1')>` 에 파일 1개씩. 목록과 분리되어 열 때만 내려받는다(30초 동기화 다운로드 폭증 방지). 최대 PDF 3MB, 이미지는 2000px JPEG로 축소 |
| 알림 발송 | GitHub Actions + Supabase REST | `.github/workflows/quality-scheduler-alert.yml` → `scripts/quality-scheduler-alert.cjs` → RTDB REST |
| 텔레그램 토큰 | 앱 설정 + 암호화 동기화 | **시스템 설정의 기존 값 재사용**(`system/settings/telegram`) — GitHub Secrets 불필요, 불편접수·미작성 알림과 같은 봇·채팅방 |
| 판정 로직 | `app.js` / 스크립트에 중복 | `js/quality-scheduler-core.js` 한 파일을 화면·발송 스크립트·테스트가 공유 |
| 로그인 | 없음 | 동김제 로그인. 등록·수정은 전 역할, **삭제는 관리자 이상** |

원본의 시드 데이터(코엔에프 제품·직원 예시)는 가져오지 않았다. 빈 상태에서 시작한다.

## 계산 규칙

- 검사 마감일 = 최근 제조(검사)일 + 주기(개월). 말일이 없는 달은 그 달 말일로 맞춘다(1/31 + 1개월 = 2/28). 원본은 JS `Date` 오버플로(→ 3/3)로 마감이 늦어졌다 — 의도적으로 바꿨다.
- 상태 우선순위: 생산 중단 > 알림 중지 > 기간 초과(D<0) > 사전 알림(D ≤ 사전 알림 일수, 기본 14) > 여유.
- 식품유형당 **대표 제품 1건**만 알림(고정한 대표 제품, 없으면 최근 제조일이 가장 늦은 제품). 유형 미지정 제품은 모두 포함.
- 성적서는 제품이 아니라 **식품유형 단위**로 인정. 해당 유형 최신 성적서 검사일 ≥ 대표 제품 최근 제조일이어야 등록된 것으로 본다.
- 보건증: 만료 후(D<0)이거나 남은 일수가 **정확히 기준일**(기본 30·7·1)인 날에만 텔레그램 발송. 화면 "임박" 표시는 가장 큰 기준일 이내.

## 배포 후 해야 할 일

1. **시스템 설정(4343)에서 텔레그램 봇 토큰·Chat ID 등록** 확인(이미 불편접수에 쓰고 있으면 추가 작업 없음).
2. GitHub Actions → `자가품질검사·보건증 일일 알림` → Run workflow → `test_send` 체크로 연결 시험 1회, `dry_run`로 본문 확인.
3. 식품유형 → 제품 → 성적서·보건증 순으로 등록(또는 제품·보건증 탭의 엑셀 양식).
4. 매일 09:00(KST) 자동 발송. 등록된 제품·보건증이 하나도 없으면 발송하지 않는다.

## 알려진 제약·리스크

- **보건증 사본에는 주민등록번호가 있다.** RTDB 규칙이 인증 없이 열려 있는 구조(CLAUDE.md '의도적으로 감수한 트레이드오프')라 주소를 아는 사람이 파일 노드를 읽을 수 있다. 뒷자리를 가린 사본 업로드를 권장하고, 보안 강화 시(커스텀 토큰 규칙) 파일 경로부터 닫는다.
- 파일은 JSON 백업·기록보관함 내보내기에 **포함되지 않는다**(`QS-ITEMS`는 기록보관함 집계에서 제외). 목록은 엑셀 다운로드로 별도 보관한다.
- 오프라인에서는 목록 조회·등록은 되지만(동기화 대기) 파일 열람·업로드는 되지 않는다.
- 자가품질검사 법정 주기·건강진단 주기(식품위생법 제40조, 시행규칙 제49조)는 사용자가 입력하는 값이며 화면에 [확인 필요]로 표기했다. 식품유형·영업 형태별 기준은 1차 출처로 확인 후 입력한다.
- 정기 관리 항목에 옛 방식으로 입력된 자가품질검사·보건증은 이관되지 않는다(위 통합 절 참고).

## 검증

`node --test tests/quality-scheduler-core.test.js` (날짜·상태·알림 대상·텔레그램 본문). 화면은 Playwright로 유형·제품·보건증 등록, 빠른 갱신, 엑셀 양식·가져오기(오류 차단 포함)·내보내기, 설정 저장을 확인했다. **텔레그램 실발송과 파일 업로드(RTDB)는 샌드박스에서 외부 접속이 막혀 확인하지 못했다** — 배포 후 위 2번과 파일 1건 업로드로 확인한다.
