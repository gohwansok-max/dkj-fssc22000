# 화면 구조와 디자인 언어

> 2026-08-12 기준. 홈페이지형 포털에서 **업무 콘솔**로 전환한 내역이다.

## 왜 바꿨나

기존 홈은 `hero(배경 이미지) → 통계 소개 → 공정 라인 → 공지사항 → 회사 소개` 구성이었다.
방문자에게 회사를 소개하는 화면이지 작업자가 쓰는 화면이 아니었다.

현장 사용자는 위생모 쓰고 태블릿을 든 작업자이고, 그가 알고 싶은 것은 하나다.
**"지금 내가 뭘 써야 하지?"**

색을 바꾸는 문제가 아니라 첫 화면이 답하는 질문을 바꾸는 문제였다.

## 브랜드 팔레트

농협 로고는 **심볼 노랑 + 워드마크 녹색** 조합이다. 두 색에 의미를 부여해
브랜드색이 곧 상태색이 되게 했다. 색이 장식이 아니라 정보를 나른다.

| 색 | 값 | 의미 |
|---|---|---|
| 녹색 | `#009a44` | 브랜드 주색 · **실시완료** |
| 노랑 | `#ffc72c` | 브랜드 심볼색 · **미점검(해야 할 일)** |
| 빨강 | `#c62828` | **미준수(부적합)** |

용어는 업계 표준을 따랐다 — `미점검 / 실시완료 / 미준수`.

토큰은 `css/dkj-tokens.css` **한 곳**에만 있다. 콘솔과 서식이 같은 파일을 읽는다.
구 `--dkj-*` 이름은 별칭으로 남겨 기존 규칙이 깨지지 않게 했다.

## 화면 구성

```
index.html  업무 콘솔 (구 index-v2)
 ├ 오늘 작성할 일지    매일 서식 6종, 상태색 타일
 ├ 작성 현황          서식별 7일 작성률 · 완료 추이 · 미작성/부적합
 ├ 월 기록 캘린더      날짜별 상태, 클릭 시 그날 상세
 ├ 주간·월간 점검
 ├ 발생 시 작성        입고검사·부적합·불만 등 9종
 └ 최근 저장된 기록

records/*.html  서식 29종
 ├ 상단 네비          주기별 탭(매일/주간월간/발생시/연간) — 현재 서식 자동 강조
 ├ 폼 헤더 + 툴바      스크롤해도 저장·인쇄 버튼 고정
 ├ 서식 본문          matrix / ledger / report 엔진이 렌더
 ├ 전자결재·감사이력
 └ 최근 저장

허브 5종  "그 문서가 어디 있나"에 답하는 화면
 ├ docs-center.html    문서센터 — 카테고리 사이드바 + 검색/상태 필터
 ├ records-center.html 기록양식 FR 목록 — 분류 + 주기 필터
 ├ mdr-register.html   MDR-001 등록대장 186건
 ├ doc-viewer.html     문서 열람 (요약 / PDF 정본 / 관련 FR 탭)
 └ record-viewer.html  FR 상세 · 연결 절차서
```

콘솔이 "오늘 뭘 써야 하나"라면 허브는 "그 문서가 어디 있나"에 답한다.
질문이 다르므로 화면 구성은 다르되, 같은 사람이 같은 태블릿에서 쓰므로
팔레트·터치 타깃·카드 형태는 공유한다.

## 태블릿 기준

12인치 가로 1280×800. **장갑 낀 손**을 전제로 터치 타깃을 잡았다.

| 요소 | 크기 |
|---|---|
| O/X 버튼 | 56px |
| 종합판정 | 60px |
| 저장·인쇄 버튼 | 46px |
| 입력칸 | 46px |
| 타일 | 최소 118px |

입력칸은 한 줄 4개(1180px 이하 3개, 900px 이하 2개, 640px 이하 1개).

## 상태 판정

`data/console-forms.json` 이 서식 목록과 **"오늘 작성했는가" 판정 방식**을 함께 정의한다.
서식마다 기입 단위가 달라 5가지로 분기한다.

| mode | 설명 | 예 |
|---|---|---|
| `dayColumn` | 주/월 시트의 **오늘 열**이 찼는가 | 작업장위생, 개인위생, 저수조 |
| `dayRow` | 1~31일 중 **오늘 행**에 값이 있는가 | 작업장온도, 세척소독제 |
| `perDay` | 오늘 날짜 기록이 있는가 | 이물관리, CCP |
| `perPeriod` | 이번 주/달에 썼는가 | 방충방서, 조도 |
| `event` | 판정하지 않고 최근 기록만 | 입고검사, 부적합, 불만 |

여러 저장 기록이 겹치면 **가장 진행된 상태**를 택한다. 임시저장본은 보관함에 아직 존재하지
않는 기록이므로 완료 집계에는 포함하지 않고, 입력값이 있으면 `작성 중`으로만 표시한다.

### 주의 — "기록 없음"은 "누락"이 아니다

생산이 없던 날은 기록이 없는 것이 정상이다. 지금은 생산일 정보가 시스템에 없어
구분하지 못하므로 캘린더 하단에 안내를 넣었다.
**생산일정이 들어오면 휴무일을 제외해 진짜 누락만 표시할 수 있다.**

## 전자결재 · 감사이력

`js/dkj-approval.js`

- **3단 결재** — 작성/검토/승인 각 단계에 이름과 시각을 확정 기록. 되돌릴 수 없다.
- **감사이력** — append-only. 수정/삭제 API 자체를 만들지 않았다.
- **해시 체인** — 각 항목이 직전 항목의 해시를 품는다. 중간을 고치면 이후가 전부 깨진다.
- **저장 훅** — 세 엔진이 모두 `DkjRecordStore.save` 를 쓰므로 저장 지점 한 곳을 감싸
  `SAVE` / `LOCK` 이력을 자동으로 남긴다. 엔진을 각각 고치지 않았다.

### 한계 (과장하지 말 것)

브라우저 로컬 저장 기준의 변조 **탐지**다. 저장소를 통째로 교체하는 공격은 막지 못하고,
해시도 암호학적 서명이 아니라 체크값이다.

**서버 도입 시 이 체인을 서버에서 재검증하는 것이 다음 단계다.**
스마트HACCP 등록의 자동기록 요건을 맞추려면 이와 별개로 센서 검·교정 이력과
통신두절 시 수기 대체 절차가 필요하다.

### 허브 재설계 때 지킨 것 (2026-08-12)

- **헤더는 콘솔과 완전히 같은 것**을 쓴다. 그래서 `.ck-header` 를 콘솔 파일이 아니라
  `dkj-tokens.css` 로 올렸다. 두 벌로 복사하면 반드시 갈라진다.
- **목록 DOM은 JS가 문자열로 만든다**(`docs-center.js` 등). 그 JS는 건드리지 않고
  내보내는 클래스명(`.doc-row`, `.cat-status`, `.status-pill`…)에 스타일만 새로 붙였다.
  선택자 이름을 바꾸면 스타일이 끊기므로 `dkj-hub.css` 머리말에 경고를 달아뒀다.
- **그라데이션 배너(`docs-hero`)를 걷어냈다.** 파란 배너는 방문자용 장식이었다.
  대신 제목 + 숫자 현황칩만 남겼다.
- **메가메뉴는 살렸다.** `menu-catalog.json` 16KB에 절차서 딥링크가 들어 있어
  버리면 이동 경로가 사라진다. 홈페이지형 GNB 대신 녹색 헤더 안 드롭다운으로 옮겼다.
  1280×800에서 실측해 오른쪽 끝 메뉴는 우측 기준으로 뒤집고, 긴 메뉴는 스크롤시켰다.
- **`css/dkj-portal.css`(1214줄) 삭제.** hero·통계·공지·회사소개 등 구 홈페이지 전용
  규칙이었고 참조가 0이 됐다. 이력에는 남아 있다.

## file:// 로 열어도 동작해야 한다

현장에서는 서버 없이 HTML을 더블클릭해 여는 경우가 있다. 그런데 `fetch()` 는
`file://` 에서 CORS 로 막히므로, JSON을 읽는 코드는 **반드시 `*.bundle.js` 폴백**을 둔다.

```
fetch('data/X.json')  →  실패하면  <script src="js/X.bundle.js">  →  window.DKJ_X
```

번들은 JSON을 그대로 전역에 감싼 파일이고 `python scripts/build-catalog-bundles.py` 로 만든다.
**`data/*.json` 을 고쳤으면 이 스크립트를 다시 돌려야 한다** — 안 돌리면 서버로 열 때는
멀쩡한데 `file://` 로 열 때만 옛날 데이터가 나오는 고약한 상태가 된다.

| 데이터 | 번들 전역 | 쓰는 곳 |
|---|---|---|
| `console-forms.json` | `DKJ_CONSOLE_FORMS` | 콘솔 홈, 서식 공통 네비 |
| `doc-catalog.json` | `DKJ_DOC_CATALOG` | 문서센터, 열람 |
| `record-catalog.json` | `DKJ_RECORD_CATALOG` | 기록양식 목록 |
| `menu-catalog.json` | `DKJ_MENU_CATALOG` | 허브 메가메뉴 |
| `mdr-catalog.json` | `DKJ_MDR_CATALOG` | MDR 등록대장 |
| `products.json` / `process-line.json` | `DKJ_PRODUCTS` / `DKJ_PROCESS_LINE` | FR-014·015·STORE-01 |

서식 엔진(matrix/ledger/report)은 스펙을 부트 JS에 넣어두므로 fetch를 쓰지 않는다 —
그래서 서식 화면 자체는 `file://` 에서도 원래 잘 떴다.
`doc-viewer` 의 요약문(`data/excerpts/*.txt`)만은 번들이 없어 `file://` 에서 핵심 포인트로
대체된다(의도된 degrade).
