# 첫 화면 로그인·사용자 권한 운영 방법

## 1. 역할 기준

| 역할 | 할 수 있는 일 |
|---|---|
| 시스템 관리자 | 사용자 계정·권한 등록·수정, 작성, 검토, 승인 |
| 책임자 | 작성, 검토, 승인 |
| 관리자 | 작성, 검토 |
| 작업자 | 작성 |

사번 **4343**(고환석)은 시스템 관리자로 고정됩니다.

## 2. 계정 관리 — 전부 웹에서 (Firebase Authentication 안 씀, 2026-08-30 변경)

로그인 계정은 **Firebase 콘솔이 아니라 `system-settings.html`에서** 시스템 관리자(4343)가 직접
등록·수정·삭제합니다. Firebase Authentication 계정을 따로 만들 필요가 없습니다.

1. 사번 4343으로 사이트 첫 화면에 로그인합니다.
2. 첫 화면 오른쪽의 **시스템 설정**을 누릅니다.
3. **+ 신규 사용자 계정 등록**에 사번·성명·역할·초기 비밀번호를 입력하고 등록합니다.
4. 그 사번으로 어느 태블릿·PC에서든 바로 로그인할 수 있습니다(로그인 화면이 뜨기 전에
   클라우드에서 최신 사용자 목록을 먼저 받아오므로, 등록 즉시 다른 기기에서도 로그인됩니다 —
   단, 그 기기가 온라인이어야 합니다. 오프라인이면 그 기기가 이전에 받아둔 목록으로 동작합니다).
5. 표시 이름·역할·비밀번호는 사용자 목록 표에서 바로 수정·저장합니다. 비밀번호 칸이 비어
   있으면(다른 기기에서 등록된 계정이라 이 기기엔 평문이 없는 경우) 바꾸려는 새 비밀번호를
   입력해야 저장됩니다 — 비워 둔 채 저장하면 안내대로 거부됩니다.

## 3. 운영 원칙

역할을 변경하기 전에 대상 직원의 담당 업무와 결재 책임을 확인합니다. 책임자는 최종 승인까지 가능하므로 HACCP팀 또는 품질책임자에게만 부여합니다. 관리자는 작성과 검토가 가능하지만 최종 승인 권한은 없습니다. 작업자는 본인 작업 기록의 작성 단계만 수행합니다.

직원이 한 번 로그인하면 각 일지의 작성·검토·승인 선택 목록에 자동으로 나타납니다. 표시 이름과 역할을 변경하는 권한은 시스템 관리자에게만 있습니다.

## 4. 주의사항 — 지금은 보안보다 사용 편의를 우선한 상태입니다

**`database.rules.json`이 인증 없이 열려 있습니다.** Firebase Authentication을 안 쓰기로 하면서,
RTDB 규칙은 "누가 진짜 관리자인지"를 더는 구분하지 못합니다. 그래서 기록·사용자 목록·텔레그램
설정·변경이력이 전부 인증 없이 읽기·쓰기가 열려 있습니다(비밀번호는 원문이 아니라 해시로만
저장·전송됩니다). 이 사이트 주소와 Firebase 설정을 아는 사람은 개발자도구로 데이터베이스를
직접 열어볼 수 있다는 뜻입니다.

이건 실수가 아니라 의도적으로 선택한 상태입니다(2026-08-30, 관리자 요청) — 여러 태블릿의
사용자 등록을 Firebase 콘솔 없이 이 화면만으로 관리하려면 지금 구조가 필요합니다. 운영이
안정되면 계정별 보안을 다시 강화할 계획입니다(예: Firebase Authentication 재도입 또는 RTDB
커스텀 토큰 검증). 그 전까지는 이 화면에 등록하는 비밀번호를 다른 중요한 계정과 같이
쓰지 마세요.
