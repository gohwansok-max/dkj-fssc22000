# 첫 화면 로그인·사용자 권한 운영 방법

## 1. 역할 기준

| 역할 | 할 수 있는 일 |
|---|---|
| 시스템 관리자 | 사용자 권한 설정, 작성, 검토, 승인 |
| 책임자 | 작성, 검토, 승인 |
| 관리자 | 작성, 검토 |
| 작업자 | 작성 |

사번 **4343**은 시스템 관리자로 고정됩니다. 다른 사용자는 처음 로그인하면 기본적으로 작업자로 등록됩니다.

## 2. 처음 설정하는 순서

1. Firebase Authentication 콘솔에서 직원 계정을 만듭니다. 계정 이메일은 `emp사번@dkj-fssc.internal` 형식을 사용합니다.
2. 저장소의 `database.rules.json` 전체를 Firebase Console > Realtime Database > 규칙에 붙여넣고 **게시**합니다.
3. 사번 4343으로 사이트 첫 화면에 로그인합니다.
4. 첫 화면 오른쪽의 **시스템 설정**을 누릅니다.
5. 직원이 한 번 로그인하면 사용자 권한 목록에 자동으로 나타납니다.
6. 표시 이름과 역할을 선택한 뒤 **저장**을 누릅니다.

## 3. 운영 원칙

역할을 변경하기 전에 대상 직원의 담당 업무와 결재 책임을 확인합니다. 책임자는 최종 승인까지 가능하므로 HACCP팀 또는 품질책임자에게만 부여합니다. 관리자는 작성과 검토가 가능하지만 최종 승인 권한은 없습니다. 작업자는 본인 작업 기록의 작성 단계만 수행합니다.

사용자가 처음 로그인하지 않았다면 목록에 표시되지 않습니다. 이 경우 먼저 Firebase Authentication에서 계정이 만들어졌는지, 직원이 실제로 한 번 로그인했는지 확인합니다.

## 4. 주의사항

GitHub Pages는 정적 사이트이므로 로그인 화면은 업무 화면의 사용을 통제하는 역할을 합니다. 실제 기록·역할 데이터의 보호는 Firebase Authentication과 Realtime Database 규칙에서 수행합니다. 따라서 규칙 게시 전에는 사용자 역할 저장·변경 기능을 운영에 사용하지 않습니다.
