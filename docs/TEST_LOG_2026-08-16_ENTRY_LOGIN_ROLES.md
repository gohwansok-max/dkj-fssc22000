# 첫 화면 로그인·역할관리 검증 기록

## 정적 검증

`node --check`로 `js/dkj-auth.js`, `js/dkj-nav.js`, `js/system-settings.js` 문법을 확인했고, 역할표와 Firebase 규칙 파일은 JSON 구문 검증을 통과했다. `scripts/smoke-check.py` 결과는 오류 0건, 경고 0건이었다. 서비스워커 사전 캐시에는 `system-settings.html`이 포함됐다.

## 첫 화면 확인

로컬 `index.html`을 로그아웃 상태로 열었을 때, 업무 콘솔 전체 위에 사번·비밀번호 입력 로그인 화면이 표시됐다. 따라서 로그인 전에는 작업자가 업무 메뉴를 조작할 수 없다. 회사소개서만 공개 화면으로 남고 나머지 업무 화면은 공통 인증 모듈에서 로그인 화면을 요구하도록 변경됐다.

## 운영 전 필수 작업

Firebase Realtime Database 규칙은 `database.rules.json`을 콘솔에 게시해야 실제로 적용된다. 게시 전에는 역할 변경·사용자 목록 저장소가 동작하지 않으며, 사번 4343의 초기 시스템 관리자 프로필도 Firebase에 생성되지 않는다.

시스템 설정 페이지도 로그아웃 상태에서 열어 확인했다. 공통 메뉴와 시스템 설정 제목 뒤에 사번·비밀번호 로그인 레이어가 표시됐고, 사용자 목록과 역할 변경 버튼은 로그인 전 노출되지 않았다. 로그인 후 Firebase 역할 저장소 규칙이 게시되어야 사번 4343 시스템 관리자에게만 실제 사용자 목록과 역할 변경 기능이 열린다.

## 운영 배포 최종 확인

PR #29로 첫 화면 로그인·사용자 권한관리 기능을 병합한 뒤, 운영 사이트에서 로그인 레이어가 초기 자동 표시되지 않는 상황을 확인했다. 즉시 초기화 안전망을 추가한 PR #30을 병합했다. GitHub Pages 배포 성공 후 `index.html`을 로그아웃 상태로 다시 확인했으며, 사번·비밀번호 입력 로그인 레이어가 업무 콘솔 전체 위에 자동 표시되는 것을 확인했다.
